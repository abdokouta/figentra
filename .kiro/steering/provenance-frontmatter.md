# Provenance frontmatter — who authored what, when

The workspace ships many long-lived Markdown artefacts — plans under
`.kiro/plans/`, audit reports under `.kiro/reports/`, ADRs under `.docs/adr/`,
runbooks under `.docs/runbooks/`. Every one is candidate authorship for BOTH
humans and AI agents. Without a machine-readable marker on the file, the
review-audit trail asks a human to reconstruct authorship from git blame — a
lossy operation once commits get squashed or an agent's commit is amended by a
human.

The **provenance frontmatter** is the workspace's answer: a small YAML block at
the top of every agent-touchable artefact naming who wrote it, when, from what
source, and whether a human has reviewed it.

Read alongside:

- [`commit-conventions.md`](commit-conventions.md) §Provenance — the commit side
  of the same contract.
- [`ai-agent-governance.md`](ai-agent-governance.md) §Enforcement — the
  reviewer's audit hook that checks for missing frontmatter.

## Precedence

1. This file wins over generic Markdown frontmatter guidance.
2. When Kiro's `inclusion:` frontmatter
   (`inclusion: always | fileMatch | manual`) is present, it lives IN THE SAME
   frontmatter block as the provenance fields. Both sets of fields coexist; no
   separate block.
3. Documents that ship no frontmatter today (every steering doc, every ADR
   authored before 2026-08-03) are grandfathered. New authoring MUST carry the
   block.

## The canonical shape

Every net-new Markdown document under the four scopes below opens with this YAML
frontmatter block:

```yaml
---
authored_by: <agent-slug OR human-handle>
authored_at: YYYY-MM-DD
source: <prompt-ref OR upstream-URL OR "human">
reviewed_by: <human-handle OR null>
reviewed_at: YYYY-MM-DD OR null
---
```

Concretely:

```yaml
---
authored_by: kiro
authored_at: 2026-08-03
source: prompt://ai-agent-first-workspace-plan
reviewed_by: null
reviewed_at: null
---
```

Or when a human authored:

```yaml
---
authored_by: akouta
authored_at: 2026-08-03
source: human
reviewed_by: null
reviewed_at: null
---
```

## Field semantics

Every field is required. `null` is a valid value only where explicitly noted.

### `authored_by` (string, required)

Identifies WHO produced the initial revision.

- For an AI agent — the agent's stable slug: `kiro`, `claude-code`, `cursor`,
  `aider`, `github-copilot`.
- For a human — the handle the workspace's other artefacts use (git email
  local-part, GitLab username, Slack handle). Consistent across the same human's
  artefacts.
- For a co-authored artefact — the primary author's identifier. Attribution for
  pair-work goes in the body ("Co-authored-by: ..." line).

Never `null`. If the artefact was auto-generated by tooling, the tooling's
canonical name lives here (`terraform-docs`, `typedoc`).

### `authored_at` (ISO 8601 date, required)

The date of first authorship — the day the file was created. Never updated on
subsequent revisions; that history lives in git.

Format `YYYY-MM-DD` (no time, no timezone). Never a full ISO 8601 timestamp —
reviewers scan a date column, not a timestamp column.

### `source` (string, required)

Identifies WHERE the content came from.

- **Agent-authored from a prompt** — `prompt://<slug>` naming the prompt or the
  plan the agent worked from. Example: `prompt://ai-agent-first-workspace-plan`.
- **Human-authored** — `human`.
- **Ported from an upstream document** — the URL or path to the upstream:
  `https://example.com/spec.md` or `.docs/adr/0054-git-commit-conventions.md`.
- **Auto-generated by a tool** — the tool's name: `terraform-docs`, `typedoc`.

The value is a HINT for reviewers. It doesn't have to resolve — a `prompt://`
URL just needs to be greppable across the transcript archive.

### `reviewed_by` (string OR null, required)

Identifies the human who has read the artefact end-to-end and accepted it.
`null` until the review lands. Once reviewed, the human's handle.

Reviewers accept an artefact by adding their handle here in a follow-up commit.
The commit message names the review scope
(`docs(governance): 📝 accept ai-agent-governance draft`).

Agent-authored artefacts always land with `reviewed_by: null`. A human's review
is what promotes them to reviewed status.

### `reviewed_at` (ISO 8601 date OR null, required)

The date of the review-accepted commit. `null` when `reviewed_by` is `null`.
Non-null when `reviewed_by` is non-null.

## Where it applies

Every new document under these scopes ships the block:

- `.kiro/plans/*.md`
- `.kiro/reports/*.md` (including subdirectories)
- `.docs/adr/*.md` (every new ADR)
- `.docs/runbooks/*.md` (every new runbook)
- `.kiro/steering/*.md` (every new steering doc)

**Grandfathered out:** documents that predate 2026-08-03 keep their original
shape until the next substantive edit touches them, at which point the block is
added.

**Excluded:** README.md files, INDEX.md files, generated content, and any
markdown that isn't authored per-project (third-party licenses, upstream
snapshots). The frontmatter would just add noise to a static index.

## Coexistence with Kiro's `inclusion:` frontmatter

When a steering doc uses Kiro's `inclusion:` frontmatter (per
[`.kiro/steering/priority-ordering.md`](priority-ordering.md)), the two field
sets share one YAML block:

```yaml
---
inclusion: manual
authored_by: kiro
authored_at: 2026-08-03
source: prompt://ai-agent-first-workspace-plan
reviewed_by: null
reviewed_at: null
---
```

Field order — Kiro's `inclusion:` first (Kiro reads first), then provenance
fields alphabetically for reviewer scan-ability.

## Update policy

Once a document is committed, its provenance frontmatter is IMMUTABLE except in
these narrow cases:

- **Adding `reviewed_by` + `reviewed_at`** — the review-accepted commit updates
  both fields.
- **Substantive rewrite** — when > 50% of the file content changes, a new
  provenance line replaces the old (the old lives in git history). The commit
  body cites the rewrite.
- **Attribution correction** — a factual correction to `authored_by` (e.g.
  crediting a co-author who worked from a shared prompt). Rare.

Every other edit — typo fixes, cross-reference updates, formatting — leaves the
frontmatter alone.

## Enforcement

Reviewers reject commits that:

- Author a new file under one of the scoped locations without the block.
- Author a new file with a partial block (any required field missing).
- Non-null `reviewed_by` alongside `reviewed_at: null` (or vice versa).
- Modify `authored_by` or `authored_at` on an existing document without the
  "substantive rewrite" caveat above.

The audit is grep-driven:

```sh
# Missing frontmatter block on a scoped artefact
for dir in .kiro/plans .kiro/reports .docs/adr .docs/runbooks; do
  find "$dir" -name '*.md' -type f 2>/dev/null | while read f; do
    head -1 "$f" | grep -q '^---$' || echo "MISSING frontmatter: $f"
  done
done

# Partial frontmatter (missing a required field)
for dir in .kiro/plans .kiro/reports .docs/adr .docs/runbooks; do
  find "$dir" -name '*.md' -type f 2>/dev/null | while read f; do
    for field in authored_by authored_at source reviewed_by reviewed_at; do
      grep -q "^${field}:" "$f" || echo "MISSING $field: $f"
    done
  done
done
```

Both return zero hits on a compliant repo.

## Anti-patterns

| Anti-pattern                                                      | Correct                                                                           |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Full ISO 8601 timestamp in `authored_at` (`2026-08-03T14:22:00Z`) | Date-only `YYYY-MM-DD` — timestamps live in git.                                  |
| `authored_by: ai`                                                 | Name the specific agent slug: `kiro`, `claude-code`, ...                          |
| `source: none` OR omitting the field                              | `source: human` when a human authored; agent-authored requires a `prompt://` ref. |
| `reviewed_by: pending` OR `reviewed_by: TBD`                      | `reviewed_by: null` — the field is machine-readable.                              |
| `reviewed_by: akouta` alongside `reviewed_at: null`               | Both non-null OR both null. Never mixed.                                          |
| Updating `authored_by` because a human copy-edited a typo         | Copy-edits do NOT change authorship. Only substantive rewrites do.                |
| Two YAML blocks (one for `inclusion:`, one for provenance)        | One block — see §Coexistence.                                                     |
| Provenance block on a README.md or INDEX.md                       | Excluded — index files are static; frontmatter adds noise.                        |

## When you're tempted

- **"But git blame already tells me who wrote it."** Git blame degrades through
  squashes, rewrites, and rebases. Frontmatter survives every history rewrite
  because it's part of the file's content.
- **"But adding YAML to every plan is friction."** It's five lines. Compared to
  the review-audit friction of tracing authorship after the fact, it amortises
  immediately.
- **"But I edited a single word — do I need to bump `authored_at`?"** No.
  `authored_at` is IMMUTABLE (§Update policy). It records first authorship, not
  last modification. Last modification lives in git.
