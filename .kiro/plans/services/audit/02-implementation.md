## 2. Entities

`AuditRecord(id,tenantId,eventId,eventType,action,actorPrincipalId,subjectPrincipalId,resourceType,resourceId,requestId,correlationId,causationId,occurredAt,recordedAt,result,reasonCode,metadataHash,previousHash,recordHash,schemaVersion)`.

`AuditExport(id,tenantId,range,status,objectRef,checksum,requestedBy,createdAt,expiresAt)`.

`RetentionPolicy(id,tenantId,eventType,retentionDays,archiveClass,effectiveAt,version)`.

`IntegrityCheck(id,tenantId,startAt,endAt,status,verifiedCount,failureCount,completedAt,checkpoint)`.

`LegalHold(id,tenantId,scope,reason,createdBy,createdAt,releasedBy,releasedAt,version)`.

Invariants: record IDs and event IDs are stable; records are immutable; tenant cannot change after append; hash fields are generated by the service; retention cannot delete held records.

## 3. Commands

- `AppendAuditRecordCommand` → `AppendAuditRecordHandler.execute()`
- `RequestAuditExportCommand` → `RequestAuditExportHandler.execute()`
- `StartIntegrityCheckCommand` → `StartIntegrityCheckHandler.execute()`
- `CreateRetentionPolicyCommand` / `UpdateRetentionPolicyCommand`
- `CreateLegalHoldCommand` / `ReleaseLegalHoldCommand`

Append accepts canonical producer metadata and validates schema version, actor/service identity, tenant context, event identity, timestamps and bounded metadata.

## 4. Queries

- `GetAuditRecordQuery`
- `SearchAuditRecordsQuery`
- `GetAuditExportQuery`
- `GetIntegrityCheckQuery`
- `GetRetentionPolicyQuery`
- `ListLegalHoldsQuery`

Filters: tenant, time range, actor, subject, resource, action, event type, result, correlation/request ID. All ranges and page sizes are bounded.

## 5. Repository ports

`AuditRecordRepository`, `AuditExportRepository`, `RetentionPolicyRepository`, `IntegrityCheckRepository`, `LegalHoldRepository`.

Required operations include append-if-absent, find-by-id, find-by-event-id, bounded search, stream-range, checkpoint update and policy/hold lookup. No mutation method exists for `AuditRecord` after append.

## 7. Ingestion and events

Canonical ingestion flow:

```text
business transaction
 → transactional outbox
 → durable transport
 → Audit consumer
 → schema validation
 → dedupe
 → hash-chain append
 → acknowledgement
```

Consumed events include canonical `AuditRecordRequested` contracts. The service publishes operational facts such as `audit.recorded`, `audit.export.completed`, `audit.integrity.failed` and retention evidence through `@stackra/contracts`.

Deduplication key is stable producer event ID. Duplicate delivery returns the existing record outcome without a second append.

## 8. Hash chain

Canonical serialization is deterministic. The implementation computes:

```text
recordHash = H(schemaVersion || canonicalRecord || previousHash)
```

The chain scope is explicitly defined per tenant/event stream. Concurrent appenders serialize chain-head updates transactionally. Integrity checks identify mismatches and gaps rather than attempting silent repair.

## 9. Persistence

```text
audit_records
audit_exports
retention_policies
integrity_checks
legal_holds
outbox
```

Indexes: `(tenant_id,recorded_at)`, actor, subject, resource, action, event ID, correlation ID, status and export state. Partitioning by tenant/time may be introduced where volume requires it without changing contracts.

Exports use Files/object storage references. Large raw payloads are not stored directly in audit rows unless explicitly classified and bounded.

## 10. Authorization and tenancy

Identity supplies authenticated principal context. IAM authorizes query/export/integrity/retention/legal-hold operations. Audit validates tenant scope and producer service identity but never evaluates business permissions itself.

System-wide audit queries require explicit system authorization and must produce their own audit evidence.

## 11. Jobs

`ProcessAuditEventJob` — durable ingestion, bounded retries, exponential backoff, DLQ.

`GenerateAuditExportJob` — streams records to object storage, checkpoints progress, calculates checksum, retries resumably.

`RunIntegrityCheckJob` — verifies hash chain in bounded ranges and records failures.

`ArchiveAuditRangeJob` — archives eligible records according to retention policy and legal holds.

`DeleteExpiredAuditRangeJob` — deletes only records explicitly eligible under policy and hold evaluation; emits deletion evidence.

## 12. Schedulers

- `audit.export.expiry` — remove expired export objects/references where policy permits.
- `audit.retention.evaluate` — identify archive/delete batches.
- `audit.integrity.periodic` — schedule bounded verification windows.

Every occurrence has an idempotency key. Schedulers never perform unbounded scans.

## 13. Security

Sensitive metadata is classified and encrypted where required. Tokens, passwords, provider credentials and secrets are prohibited from audit metadata. Query responses are field-filtered by IAM role and data classification. Export links are short-lived and authorization checked.

## 14. Observability

Metrics: ingestion lag, append latency/failures, duplicate rate, DLQ depth, query latency, export throughput/failures, integrity failures and retention backlog.

OTel spans contain request/correlation/causation identifiers but not full audit payloads or secrets. Logger output is metadata-only.

## 15. Tests

Unit: immutable record invariant, canonical hashing, chain verification, retention eligibility, legal-hold precedence.

Integration: concurrent append serialization, outbox ingestion, duplicate events, PostgreSQL persistence, object-storage export and checkpoints.

Contract: audit event schemas and producer compatibility.

Security: tenant escape, unauthorized export, service identity forgery, sensitive-field leakage.

E2E: producer transaction → audit ingestion → query → export → integrity verification.

Load: sustained append throughput, bounded query latency, concurrent exports.

Failure: database outage, object-storage outage, duplicate delivery, poison event, consumer restart and checkpoint recovery.

## 16. Deployment

Database migrations are expand/contract and rolling-deployment safe. Consumer/worker concurrency is configurable per environment. DLQ replay is an explicit operator action and remains idempotent.

## 17. Definition of done

Every auditable contract has a schema version and producer identity. Every record is immutable and tenant-isolated. Ingestion is durable and idempotent. Hash verification is operationally usable. Retention/legal hold is enforced. Exports are authorized and checksummed. No audit data is treated as application logs, telemetry, analytics or authorization state.
