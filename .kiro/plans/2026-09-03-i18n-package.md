# @stackra/i18n — architecture plan

**Status:** Planned **Anchor ADRs:**
[ADR-0091](../../.docs/adr/ADR-0091-cross-runtime-package-structure.md),
[ADR-0092](../../.docs/adr/ADR-0092-service-auto-registration.md) **Reference:**
`.ref/packages/i18n/` (`@stackra/i18n` v0.1.0) — already has full cross-runtime
layout **Depends on:** `@stackra/container`, `@stackra/contracts`,
`@stackra/logger`

## Purpose

`@stackra/i18n` is the workspace's canonical internationalization layer.
Enterprise requirements day one:

- **Type-safe key resolution** — TypeScript literal-type inference from JSON
  catalogues gives compile-time `t("login.title")` autocomplete + typo
  detection.
- **Cross-runtime** — same API on browser, RN, Cloudflare Worker, NestJS server.
- **3 catalogue loaders** — static (bundled), HTTP (remote), dynamic-import
  (code-split).
- **Vite auto-discovery plugin** — walks
  `packages/*/src/core/i18n/{en,ar}.json`, hot-reloads on save.
- **RN device-locale** — reads system locale via `expo-localization` /
  `react-native-localize`.
- **RTL/LTR direction** — automatic per locale; exposed via `useDirection()`;
  wires into `document.dir` on web.
- **Fallback chain** — `ar-EG → ar → en` (base locale then default).
- **Interpolation** — ICU MessageFormat for plurals, gender, dates.
- **Nested keys** — `t("errors.validation.required")`.
- **Namespacing per package** — every `@stackra/*` package's catalogue
  auto-registered under the package's slug: `t("rbac:roles.title")`.
- **Locale persistence** — AsyncStorage (RN), cookies (Node/Nest), localStorage
  (browser).
- **NestJS per-request locale** — middleware reads `Accept-Language` + session,
  binds per-request locale via `IRequestContext`.
- **CLI** — `i18n:generate-types` builds `.d.ts` from catalogues;
  `i18n:validate` checks parity across `en.json` + `ar.json`.

## Non-goals

- Full translation-management UI (that's a separate admin service).
- Machine translation (external service — Google/DeepL/OpenAI wrapped by an
  optional `/translate` subpath, but out of scope for v1).
- Complex plural rules for exotic locales (Arabic dual/paucal handled via ICU;
  other complex rules escalate to the app).

## Core API (locked)

```typescript
interface II18nService {
  // Read
  t(
    key: string,
    vars?: Record<string, unknown>,
    options?: ITranslateOptions,
  ): string;
  has(key: string): boolean;

  // Locale management
  setLocale(locale: Locale): Promise<void>;
  getLocale(): Locale;
  getSupportedLocales(): readonly Locale[];

  // Direction
  getDirection(locale?: Locale): Direction;

  // Introspection
  keys(): readonly string[];
  catalogue(locale?: Locale): Readonly<Record<string, unknown>>;

  // Subscriptions
  onLocaleChange(handler: (locale: Locale) => void): () => void;
}

interface ITranslateOptions {
  fallback?: string;
  namespace?: string; // override package's slug
  defaultLocale?: Locale;
}
```

## Loaders (from .ref)

- `StaticLoader` — bundled JSON at compile time. Every `@stackra/*` package
  ships `src/core/i18n/{en,ar}.json` per
  `.kiro/steering/frontend-localization.md`.
- `HttpLoader` — fetches catalogues from a remote translation service. Cache
  - revalidate on interval.
- `DynamicImportLoader` — code-split per locale via
  `import(`./locales/${locale}.json`)`.

## Type generation

`i18n:generate-types` walks every package's `src/core/i18n/*.json`, generates
`i18n.types.d.ts` with:

```typescript
// Auto-generated — do not edit
declare module "@stackra/i18n" {
  interface II18nKeys {
    "login.title": {}; // no vars
    "login.error.credentials": {};
    "welcome.greeting": { name: string }; // typed vars from ICU {name}
    "cart.summary": { count: number }; // plural markers detected
  }
}
```

Then `t("login.title")` autocompletes; `t("bogus.key")` fails typecheck.

## Vite plugin

```typescript
// vite.config.ts
import { i18nPlugin } from "@stackra/i18n/vite";

export default defineConfig({
  plugins: [
    i18nPlugin({
      packages: "packages/*/src/core/i18n/*.json",
      defaultLocale: "en",
      supportedLocales: ["en", "ar"],
      hmr: true,
    }),
  ],
});
```

At build time:

1. Walks every `packages/*/src/core/i18n/*.json`.
2. Merges into per-locale bundles under the package's slug namespace.
3. Emits `virtual:stackra-i18n` module — one JS ESM export per locale.
4. In dev, HMR: JSON edit → catalogue reload → subscribers re-render.

## RN device locale

```typescript
import * as Localization from "expo-localization";
// or
import { getLocales } from "react-native-localize";

const deviceLocale = Localization.locale; // "ar-EG"
```

RN provider reads on mount + falls back through the chain. Manual override
persists to AsyncStorage.

## NestJS middleware

`LocaleResolutionMiddleware` reads (in order):

1. Explicit query param `?lang=ar` (dev tool).
2. Session cookie `X-Locale`.
3. `Accept-Language` header.
4. Default locale.

Binds to `IRequestContext.locale`. `@I18nLang() locale: Locale` decorator
injects into Nest handlers.

## Direction service

Locales carry direction metadata:

```typescript
{
  ar: { direction: "rtl" },
  he: { direction: "rtl" },
  fa: { direction: "rtl" },
  ur: { direction: "rtl" },
  en: { direction: "ltr" },
  // ...
}
```

Web `<I18nProvider>` writes `document.documentElement.dir = direction`. RN uses
`I18nManager.forceRTL(direction === "rtl")` (requires app restart per RN docs —
documented in `.docs/i18n/rtl.md`).

## Success criteria

- [ ] 8 subpath exports build cleanly.
- [ ] Type-safe: `t("bogus.key")` fails typecheck.
- [ ] Vite plugin auto-discovers `packages/*/src/core/i18n/*.json` + HMR.
- [ ] RTL: setting locale to `ar` sets `document.dir = "rtl"`.
- [ ] Fallback: `ar-EG` missing key → falls to `ar` → falls to `en`.
- [ ] NestJS: `Accept-Language: ar` → handler sees `locale = "ar"`.
- [ ] RN: device locale honored on first mount.
- [ ] CLI `i18n:validate` fails when `en.json` + `ar.json` diverge.
