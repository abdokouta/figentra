# i18n — implementation plan

Localization abstraction for messages, formatting, locale negotiation and RTL-aware metadata across web/mobile/desktop.

## API
Typed message catalogs, locale resolver, translator, number/date/currency formatters and fallback policy. Catalog loading is explicit and bounded.

## Security/testing
No executable catalog content; validate catalog schemas and locale identifiers. Test fallback, pluralization, RTL metadata, missing keys and runtime loading failures.

## Exit criteria
All apps share one localization contract with deterministic fallback and no product-domain ownership.
