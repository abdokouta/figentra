Docs · Framework · @stackra/container

@stackra/container

NestJS-compatible dependency injection for the workspace's TypeScript packages. Runs identically in Node, Vite, React Native, and web-workers — one container primitive, every runtime.

Version 1.4.0 Framework tier Maturity · stable Owner · framework-core-builder

@stackra/container ships the DI runtime every @stackra/* feature package depends on. It composes on top of reflect-metadata and follows the NestJS Provider + DynamicModule + lifecycle-hook contract exactly — engineers moving from a NestJS backend recognise every primitive.

Install

# pnpm
pnpm add @stackra/container reflect-metadata

# peer requirement — every workspace app imports this once
# at the entry point BEFORE the container boots.
import "reflect-metadata";

Quick start

A minimal module + service + top-level composition looks like this: 

import { Module, Injectable } from "@stackra/container";

@Injectable()
class LoggerService {
  info(msg: string) {
    console.log(`[log]`, msg);
  }
}

@Module({ providers: [LoggerService], exports: [LoggerService] })
class AppModule {}

const app = await Container.create(AppModule);
const logger = app.get(LoggerService);
logger.info("container booted");

Lifecycle

Services extending OnModuleInit run their onModuleInit hook after every dependency has been resolved. Discovery loaders extend OnApplicationBootstrap — the phase after every module has finished init. Never do side-effect work inside a constructor.

API reference

@Module(options) decorator
Declares a container module. Options: providers, imports, exports, global.
@Injectable() decorator
Marks a class as injectable. Reflects constructor parameter types for DI resolution.
@Inject(token) parameter decorator
Overrides the reflected type with an explicit DI token (string or symbol) — used for interfaces and cross-package contracts.
Container.create(RootModule) async factory
Boots the container. Runs every module's onModuleInit, then every service's onApplicationBootstrap. Returns an application instance with .get(ClassOrToken).

Lifecycle hooks

Every provider MAY implement one or more lifecycle interfaces. Hooks fire in the order Container.create resolves them.

OnModuleInit

Fires once per provider after its dependencies are resolved. Use for module-local initialisation — seeding a registry with config-driven values, warming a memoisation cache.

OnApplicationBootstrap

Fires once per provider AFTER every module has finished onModuleInit. Use for cross-module coordination — discovery loaders scan the container for @AsController-marked classes; feature registrars extend base registries with per-feature contributions.
